# raw-ask — 登録済みの論文から答える（無ければ Web で、URL つき）

研究の質問に、**まず自分の Paper DB（登録済みの論文の要約）を根拠に**答える。Paper DB に無ければ **Web で探し、主張ごとに出どころの URL を示す**。スキルの名前を知らなくても使えるよう、`office/` の決まりにも「研究の質問には、まず登録済みの論文から答える」と書いてある。

## いつ使うか

- 「○○の先行研究は？」「〜という報告はある？」「○○の文献値（障壁・収率・格子定数…）は？」「この反応の機構は？」「○○と△△の手法の違いは？」「○○って何？」
- 自分が文献値と比べたり、引用したりしようとしているとき（`raw-write` で書いているときも）
- 使わない: 自分のデータの解析（`raw-analyze`）、まだ持っていない論文を一覧にして集めたいとき（`raw-research`）

## はじめてモードを尊重する

`office/CLAUDE.md`（Codex CLI では `AGENTS.md`）の冒頭に `> 運用モード: はじめて` があれば、平易な日本語で答え、専門用語は初出で 1 行説明し、最後に「次はこれをしましょう」を 1 つだけ示す。

`${SKILL}` = このスキルの install 位置（Claude Code: `~/.claude/plugins/marketplaces/*/skills/raw-ask/`）。以下のコマンドの `${SKILL}` を実パスに置換して実行する。Windows では `python3` を `py` に読み替える。

## ワークフロー

### Step 1: 問いを検索の言葉にする

質問から、**日本語と英語の言い換えを 2〜4 本**作る（専門用語・略語・同義語。例「固相反応の活性化障壁」→「activation barrier solid-state reaction」「結晶中の反応 速度論」）。要約は日本語と英語が混ざっているので、両方で探す。

### Step 2: 登録済みの論文を探す（必ず最初に）

```bash
python3 ${SKILL}/scripts/search_library.py "言い換え 1" "言い換え 2" "言い換え 3"
```

- プロジェクトの `work/papers/md` を自動で探す（別の場所なら `--library`）。読むのはフォルダの直下の `.md` だけ（サブフォルダは読まない）。結果の 1 行目に**登録済みの本数とフォルダ**が出る（読めないファイルは数に入れず、別に挙がる。文字コードを推定して読んだファイルも挙がる。どちらも UTF-8 で保存し直すよう伝える）
- 「検索語がありません」と出たら、よくある語・記号だけの問いになっている。専門用語・英語・2 文字以上の語で言い換える
- 点数は「どれから読むか」の目安。**上位の要約の該当する節を実際に読み**、問いに答えているかで判断する（点数だけで「ある・無い」を決めない）
- 当たりが無ければ、言い換え（英語・別の用語・上位の概念）でもう 1 回探してから「登録済みの N 本には見当たらない」とする

### Step 3: 数値や条件まで要るときは PDF を読む

要約には表の値・SI・図の細部が無いことがある。要約の frontmatter の `pdf_local`（`work/papers/pdf/`）を、必要なページだけ読む（全体を一度に読まない）。**文献値は表・脚注まで辿り、条件（温度・基準状態・単位・どの量か）を確かめてから**使う（`office/` の「確かめ方の決まり」）。

### Step 4: Paper DB に無い・足りないときは Web で探す

1. **論文のデータベース**（`raw-research` と同じ）: OpenAlex・Crossref・Semantic Scholar・arXiv・PubMed の API で、問いに答えていそうな論文を探し、要旨を読む
2. **一般の Web 検索**（WebSearch・WebFetch）: 解説・公式の資料・データベースの値など。**一次資料（論文・公式の文書・データベース）を優先**し、ブログやまとめは補助にとどめる
3. **Web から得た主張には、必ず出どころの URL を文中に付け、「（Paper DB 未登録）」と明記する**。Paper DB の根拠と同じ重みで混ぜない
4. Web も使えないとき（オフライン等）は、そう書いたうえで、ユーザーに資料を渡してもらうか、わかる範囲で答える。後者の文には「（根拠なし・推測）」と付ける

### Step 5: 答える

次の形で答える：

```
結論: <問いへの答えを 1〜3 文。分かっていないことは分かっていないと書く>

Paper DB の根拠:
- <著者 年, 誌名>（work/papers/md/<ファイル>.md、節「<節名>」）: <その論文が言っていること。数値は単位と条件つき>

Web の根拠（Paper DB 未登録）:
- <出どころの名前>: <言っていること> — <URL>

分からないこと・食い違い:
- <論文どうしの食い違い、条件の違い、見つからなかったこと（調べた範囲も書く）>
```

- 「結論」の中でも、Web に頼る文には URL と「（Paper DB 未登録）」の両方を付ける（根拠の種類と出どころが読んで分かるように）
- Paper DB にも Web にも出どころの無い文（自分の知識だけで書く文）は「（根拠なし・推測）」を付け、結論の根拠にしない
- 登録済みの論文で答えられたら、Web の根拠は省いてよい
- 「無い」と言うときは、調べた範囲（登録済み N 本・使った言い換え・Web で探した先）を書く（`office/` の「確かめ方の決まり」の 3）

### Step 6: 記録と、Paper DB を育てる

- 問いと答えの要点・出どころを `work/topics/qa/YYYY-MM-DD.md` に追記する（その日のファイルがあれば追記、無ければ作る）
- Web で見つけた論文が役に立ったら、「この論文を Paper DB に登録しますか？（PDF を `work/papers/pdf/` に入れて『登録して』）」と提案する。**勝手に登録しない**

## 他スキルとの関係

- **`raw-register`** が作った要約を読む。役に立った論文の登録も `raw-register` に回す
- **`raw-research`** は「まだ持っていない論文を一覧にする」、**`raw-ask`** は「問いに答える」
- **`raw-write`** で書いているときに文献値を引くなら、`raw-ask` で根拠を確かめてから事実の一覧（`facts.md`）に出どころつきで足す

## 重要な注意事項

- **根拠の無い主張をしない**。Paper DB にも Web にも根拠が無いことは、推測と明記する
- **Web の主張には必ず URL**。URL を付けられない主張は書かない
- **Paper DB の根拠と Web の根拠を分けて書く**（登録・要約を経た根拠とそうでない根拠は重みが違う）
- 答えの記録は `work/topics/qa/` に（`office/` には書かない）
